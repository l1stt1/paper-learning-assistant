# 文章导读写作要求

目标是让尚未读过论文的读者理解：作者想解决什么，为什么这样设计研究，每组分析得到了什么，以及这些发现怎样推动下一个问题。用研究逻辑串联全文，同时保留影响理解的证据限制。不要把导读写成术语考试、数字清单或主要由局限性组成的审稿意见。

## 从原文到研究主线

1. **确认材料。** 核对论文身份、正文版本、阅读PDF页码与补充材料范围。只使用实际提供的资料。不声称访问了未提供的全文、知识库或互联网；身份与发表状态未外部核验时如实说明。
2. **先理解整篇，再写局部。** 阅读摘要、引言中的问题与知识缺口、各结果段、主图和图注，按需要回查方法与补充图。画在图里的筛选步骤、对照、坐标、分组和结果须实际查看图像；不能仅靠PDF文本提取或摘要推测图意。
3. **整理作者的推进关系。** 先形成一条简洁主线：起始问题 → 关键分析 → 主要发现 → 下一步为何必要。遇到并行研究路线应明确分叉，不强行串成因果链。此步骤可以在工作笔记中完成，不要求用户另行审批或生成独立报告。
4. **按科学问题分节。** 通常以主图及对应结果段为单位；同图承担不同科学问题时可拆节，相邻图共同回答一个问题时可合节。方法学论文或综述按其真实论证结构调整，不固定章节数。
5. **明确证据对象。** 核查主要计数、比例的对象和分母，区分发现集、筛选子集、验证集与不同实验材料。正文、图、图注出现冲突时先查方法和补充材料，仍未解决就明确指出；不能默默拼接出更强结论。缺失非关键补充材料作为已知限制，不把补齐全部附件当作开始有效阅读的前提。

## 写作内容

**全文概览**回答总科学问题，说明作者的研究路线与分叉，概括最重要的发现。主要发现写结果及其意义，不用计算参数或定义清单代替。解释边界另行保留，但结果本身需要的限定语不能全部藏进折叠区。

**逐节导读**应让读者不看论文也能知道这一节要研究什么，再带着问题去读图。每节依次交代：

- 本节科学问题：研究对象、未知点和比较关系明确。
- 为什么做这一步：连接前一节留下的问题或全文知识缺口，不只是把科学问题换一种说法。
- 分析思路：说明样本或实验体系、核心比较、主要方法及必要对照；细节以有助于理解设计为限。
- 主要发现：通常用两句简洁中文概括关键结果和它回答了什么。区分“进行了某分析”和“分析发现了什么”，避免只罗列数字。
- 带着原文思考的问题：通常1–2个，来自本节真正要解决的科学问题。优先提炼原文研究目的；从实验设计归纳时，不冒充作者原话。不要把所有问题都写成术语释义、分母记忆或“为什么不能推出某结论”。
- 下一步：解释当前发现如何引出后续实验；最后一节可总结两条路线如何汇合及尚待解决的科学问题。

标题表达本节主要发现或核心问题，避免只写“定义辨析”“证据层级”等笼统标签。概念卡只整理理解该文所必需的概念，先通俗解释，再说明本文怎样使用它。跨文对照先比较科学问题、研究路线和发现，再用分析对象、实际采用的对照或比较基准以及研究方法解释异同。

**中文语境检查**覆盖标题、概览、逐节导读、概念、比较和来源说明。按领域用法与整句科学含义表达，不逐词硬译；尤其检查动词的主语、研究意图、比较对象和结论强度。含义可能不清的专名首次出现时可保留英文并解释其在本文中的具体用法。同一词在不同上下文中允许不同表达，不建立针对用户例子的机械替换词表。

## 保存到现有阅读格式

新编导读按以下结构组织；旧文章保留已有字段及扩展信息。下表兼有阅读器使用的字段和新导读的写作要求，不代表旧JSON缺少新增字段就无法运行。内容字段写普通文本，当前阅读器不会渲染字段内的Markdown；不要把加粗标记或标题语法当作展示效果。

| 位置 | 内容与类型 |
| --- | --- |
| `paper_id`、`page_convention` | 文献身份和阅读PDF页码约定，均为字符串。文献身份与资料库的 `article_id` 是不同对象。 |
| `overview.question` | 全文科学问题，字符串。 |
| `overview.logic` | 全文研究路线及必要分叉，字符串；前端优先显示它。 |
| `overview.approach` | 简洁的方法概述，字符串；保留该字段，旧内容缺少 `logic` 时前端以它回退。 |
| `overview.findings`、`overview.limits` | 主要发现、关键限制，各为字符串数组。 |
| `sections[]` | 每项有稳定 `id`、`title`、`pages`，以及下列正文结构。 |
| `guiding_question`、`rationale`、`approach` | 本节问题、动机、分析思路，各为字符串。 |
| `summary`、`evidence` | 主要发现与可定位的原文依据，各为字符串；重要数量保留其对象和范围。 |
| `questions` | 作者视角的科学问题，字符串数组。 |
| `transition`、`caution` | 后续推进关系、影响理解的限制，各为字符串；无特定限制时不生造风险。 |
| `concepts[]` | 每项包含 `id`、`term`、`aliases`、`plain`、`technical`、`paper_context`、`pages`、`related`、`boundary`；别名与关联ID为数组，解释为字符串。 |
| `comparison` | `question`、`unit`、`cohort`、`normal`、`definition`、`evidence`、`limits` 七项，各为 `{ "text": "...", "pages": [...] }`。无适用比较时说明原因，不编造正常对照或队列。 |
| `source_coverage`（已有则保留） | 简要列出实际阅读/查看的文件与页段、可用附件及缺件；新文章也可把覆盖范围记在已有来源说明中，不必为格式齐全新增审计字段。未看过的页不能列为已核查。 |

`pages` 一律为当前阅读PDF中真实存在的、从1开始的整数数组，不是印刷页码，也不是数字字符串。独立附件的页码不能直接填入主阅读PDF的跳转字段；在来源说明中注明其文件和页段。`articles.json` 的页数也须与实际PDF一致，不要用不存在的页码填满字段。

`article_id`、`section.id`、`concept.id` 与个人记录关联：修改已整理文章时保留原ID，新增部分才创建稳定且唯一的ID。已导入文章继续使用其 `imported-...` ID及原 `paper_id`（身份有误时先核查），不因整理完成重建文章或改名；`imported: true` 可以保留；导入文章至少要有实际章节内容，界面才会从“尚未整理”转为“文章导读”，仅补总览不够。概念的 `related` 只引用本篇实际存在的概念ID；不要使用个人自建概念机制预留的 `custom-` 前缀。不得把已写入SQLite的个人概念、笔记和问答复制进预制JSON。

## 来源与核查边界

关键结果、数量与概念解释须有可定位原文。生成内容是 AI 整理稿；页码与摘录匹配不能证明科学解释正确，也不等于独立人工核查。保留缺件、冲突、阴性结果及解释限制，不编造未做过的验证。
